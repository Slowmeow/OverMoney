# OverMoney — продукты по бюджету

Планировщик недельного меню, который держит три вещи одновременно: **бюджет**, **калории с БЖУ** и **то, что уже лежит дома**.

Вы говорите: «15 000 ₽ в месяц на двоих». Приложение собирает неделю блюд под ваши нормы, разворачивает её в список покупок с реальными упаковками и ценами, вычитает содержимое кладовой и, если не влезает в деньги, **удешевляет рацион заменами, не трогая калории и белок**.

## Как запустить

**На компьютере:** двойной клик по `start.bat`. Браузер откроется сам — но не раньше, чем сервер будет готов отвечать. Приложение работает на `http://localhost:8777/`. Нужен установленный Python (он уже есть).

**На телефоне — по адресу.** Основной способ, работает и на Android, и на iPhone:

```
https://slowmeow.github.io/OverMoney/
```

Откройте на телефоне и добавьте на главный экран: Android — Chrome, меню ⋮ → «Добавить на главный экран»; iPhone — Safari, «Поделиться» → «На экран «Домой»». Дальше приложение запускается с иконки в полный экран и работает без интернета: при первом открытии оно целиком уезжает в память телефона.

Обновляется само — при каждом `git push` GitHub пересобирает страницу, а приложение подхватывает правки при следующем запуске.

**На телефоне — одним файлом, без интернета вообще.** Если адрес недоступен или нужен полностью автономный вариант:

```
python build.py          собирает overmoney.html — 390 КБ, всё внутри
```

Отправьте `overmoney.html` на телефон любым способом. **Только на Android** и с одной оговоркой: файл надо сначала сохранить в «Загрузки» и открывать оттуда. Если открыть его прямо из мессенджера, страница попадёт в браузер по адресу `content://`, а таким страницам браузер запрещает что-либо сохранять — приложение будет выглядеть рабочим, но потеряет всё при закрытии вкладки. Оно об этом предупредит красным на первом экране. На iPhone этот путь не работает вовсе: iOS не даёт запускать локальный HTML как приложение.

**На телефоне — через компьютер.** Пока `start.bat` работает, откройте на телефоне адрес вида `http://192.168.x.x:8777/` (он печатается в окне запуска, телефон должен быть в той же сети). Единственный режим, где компьютер и телефон работают с **общей базой** — файлом `data.json` рядом с приложением, — и правки с любого устройства видны везде.

Во всех остальных режимах данные живут в том браузере, где вы работаете. Перенос — через «Настройки → Данные → Выгрузить в файл» и загрузку копии на другом устройстве. Браузер может очистить своё хранилище сам, поэтому копию стоит выгружать раз в месяц.

## Что оно делает

- **Считает нормы** по формуле Mifflin-St Jeor для каждого едока отдельно (пол, возраст, рост, вес, активность, цель). Любую цифру можно перебить вручную.
- **Собирает неделю** из ~60 рецептов, подгоняя порции под калорийную долю каждого приёма пищи. Супы и рагу по умолчанию растягиваются на два дня.
- **Приоритезирует кладовую.** Внесли «картошка 4 кг, гречка 800 г» — приложение и меню перекроит в их сторону, и из списка покупок вычтет. В тестах это срезало неделю с 4629 ₽ до 3212 ₽.
- **Считает по упаковкам, а не по граммам.** Нужно 300 г риса — в списке будет пачка 800 г и её полная цена, а 500 г уйдут в кладовую на следующую неделю.
- **Удешевляет при нехватке бюджета** — заменами внутри роли: сыр → творог, фарш свино-говяжий → курица, гречка → перловка, батон → ржаной. Каждая замена откатывается, если калории уходят из допуска или белок падает ниже установленной границы.
- **Честно сдаётся,** когда бюджета не хватает физически: показывает самый дешёвый вариант, сохраняющий норму, и называет сумму, при которой задача решается.

## Про цены — важно

Стартовые цены в каталоге — это **оценка** уровня Пятёрочки и Магнита, а не живые данные. Они помечены знаком `~` и словом «не проверено».

Точность появляется после вашей первой закупки: в списке покупок у каждой позиции есть поле цены — поправьте там, где чек разошёлся с расчётом. Правка сохраняется с датой, и всё старше 30 дней снова помечается как непроверенное. Через две-три закупки каталог становится вашим личным и цифры сходятся с реальностью.

## Как проверить, что цифры не врут

```
node tests/run.js
```

74 проверки за пару секунд, без установки чего-либо. Проверяется не «нажимается ли кнопка», а то, на что приложение опирается молча: что норма питания согласована сама с собой и совпадает с формулой Mifflin-St Jeor, что калорийность продуктов сходится с их БЖУ, что сумма стоимостей блюд равна чеку до копейки, что купленного хватает на все рецепты, что из кладовой не берётся больше, чем в ней лежит, что даты не уезжают на сутки, что подгонка под бюджет не достигает экономии недокормом и что при объединении хозяйств бюджеты складываются правильно, даже если заданы за разные периоды.

Планировщик намеренно случаен, поэтому всё, что от него зависит, гоняется на **фиксированных посевах** генератора случайных чисел. Без этого два прогона несравнимы: непонятно, план подешевел от правки в коде или просто выпал другой набор блюд. В конце печатается быстродействие — на тех же посевах, поэтому цифры сравнимы между запусками.

Облачный слой — вход, хозяйства, слияние, расхождения — проверяется отдельно, против поддельного сервера:

```
node tests/cloud.js
```

42 проверки. Настоящий код приложения работает против подделки, повторяющей поведение `schema.sql`; два отдельных окна изображают два устройства, у каждого своё хранилище. Проверяется то, что нельзя увидеть глазами: не затирает ли второе устройство работу первого, доживает ли до сервера последняя правка цены, уносит ли выход из аккаунта чужие данные на общем телефоне, обновляется ли молча истёкший ключ и что происходит, когда пропала связь. Отдельно — что чужое хозяйство не читается и не перезаписывается.

Именно этот тест поймал ошибку, которую иначе нашёл бы только пользователь: вступая в чужое хозяйство, человек оставался и в своём, и после следующего входа попадал в старое.

Отдельно проверяется, что все восемь экранов действительно строятся:

```
npm install jsdom     один раз
python build.py       собрать overmoney.html
node tests/render.js
```

Без jsdom этот тест честно пропускает себя, а не притворяется пройденным. Берёт он именно собранный `overmoney.html` — так заодно проверяется, что версия для телефона склеена в рабочем порядке.

## Аккаунты и синхронизация

Без настройки приложение работает целиком в браузере: аккаунтов нет, данные никуда не уходят и между устройствами сами не переходят. Чтобы включить вход и синхронизацию, нужен бесплатный проект Supabase. Настраивается один раз, минут за пятнадцать.

**1. Завести проект.** [supabase.com](https://supabase.com) → зарегистрироваться → **New project**. Имя любое, регион — ближайший, пароль базы придумайте и сохраните (он понадобится только если полезете в базу руками). Проект поднимается пару минут.

**2. Создать таблицы.** В проекте слева **SQL Editor** → **New query**. Откройте файл [`supabase/schema.sql`](supabase/schema.sql), скопируйте его целиком, вставьте и нажмите **Run**. Должно ответить `Success`. Запускать повторно безопасно.

**3. Забрать два значения.** Слева **Project Settings → API**: оттуда нужен **Project URL**. И **Project Settings → API Keys**: оттуда — **публикуемый** ключ (`sb_publishable_…`; в проектах постарше он называется `anon public` и начинается с `eyJ`).

**4. Вписать их в код.** Откройте `js/core/config.js` и подставьте:

```js
const CONFIG = {
  supabaseUrl: 'https://ваш-проект.supabase.co',
  supabasePublishableKey: 'sb_publishable_...'
};
```

### Про ключи — единственное место, где легко навредить

В проекте два ключа, и путать их дорого.

**Публикуемый** (`sb_publishable_…` / `anon`) — публичный **по замыслу**. Он обязан лежать в коде страницы, его видит каждый, кто откроет исходник, и спрятать его в приложении без сервера физически невозможно: любая попытка была бы не защитой, а её изображением. Прятать и нечего — сам по себе он не открывает ни одной строки. Кто что может прочитать, решают правила в базе, а они спрашивают, **кто вошёл**, а не какой ключ предъявлен.

**Секретный** (`sb_secret_…` / `service_role`) — полная противоположность. Он обходит все правила разом и открывает данные всех пользователей проекта. В код его класть нельзя никогда, ни в каком виде, ни «временно». Ему место только на сервере, которого у этого приложения нет.

Если секретный ключ куда-то утёк — в переписку, в снимок экрана, в чужие руки — отзовите его немедленно: **Project Settings → API Keys → Revoke**. Приложение этим ключом не пользуется, поэтому отзыв ему ничем не грозит.

**5. Выложить.** `git add -A && git commit -m "подключил облако" && git push`. Через минуту GitHub Pages обновится, и на сайте появится вкладка «Аккаунт».

**Подтверждение почты.** По умолчанию Supabase шлёт письмо со ссылкой, и до перехода по ней войти нельзя. Для себя и близких это можно отключить: **Authentication → Providers → Email** → выключить **Confirm email**. Если приложением будут пользоваться посторонние — оставьте включённым.

### Как это работает для людей

Каждый регистрируется по почте и паролю и получает своё **хозяйство** — это то, чему принадлежат бюджет, кладовая, цены и меню. Пока человек в хозяйстве один, это просто его данные.

Чтобы вести бюджет вдвоём, один открывает «Аккаунт» и диктует второму **код приглашения**. Второй вводит код у себя — и хозяйства объединяются:

- бюджеты **складываются**, приводясь к одному периоду;
- профили обоих становятся едоками одного меню;
- кладовая складывается по количествам, журнал цен объединяется;
- план на неделю отбрасывается и собирается заново — прежний считался на другой состав едоков.

Что именно изменится, показывается списком **до** согласия: разделить обратно слившееся приложение не умеет.

Выйти из общего хозяйства можно в любой момент — вам заведётся своё, с копией текущих данных. Остальные участники ничего не теряют.

### Что важно знать

Данные после входа лежат в вашем проекте Supabase — то есть у вас, а не у меня и не у GitHub. Приложение по-прежнему работает офлайн: браузер остаётся рабочей копией, облако подтягивается следом.

Выход из аккаунта **стирает данные с устройства** — чтобы их не увидел следующий, кто откроет приложение здесь. В облаке они остаются.

Если два устройства правят данные одновременно, тот, кто записался вторым, получит расхождение, а не молча затрёт чужую работу.

## Безопасность

Код открыт, поэтому честно назвать модель угроз важнее, чем обещать «всё защищено».

Сервера у приложения нет, аккаунтов нет, секретов в коде нет, чужих библиотек нет ни одной. Данные лежат в браузере того, кто ими пользуется, и никуда не отправляются: в коде **ноль внешних адресов**, и правила `Content-Security-Policy` не выпускают запросы за пределы своего адреса, даже если такой появится по ошибке. Красть с сервера нечего, потому что сервера нет.

Остаётся два способа навредить, и оба проверяются `node tests/security.js`:

- **Выполнить чужой код через присланный файл выгрузки.** Названия продуктов, марки, магазины, имена профилей и шаги рецептов приходят из файла и выводятся на экран. Всё выводится через `textContent`, поэтому разметка в них остаётся текстом. Ветки `html:` в сборщике элементов нет намеренно — она была, ей никто не пользовался, и один неосторожный вызов превратил бы файл в способ выполнить код.
- **Испортить данные так, чтобы приложение перестало открываться.** Злого умысла для этого не нужно: файл выгрузки рвётся при пересылке сам. Раньше это окирпичивало приложение навсегда — битое состояние сохранялось и переживало перезагрузку. Теперь всё, что приходит извне, приводится к нужному виду: типы полей, типы элементов внутри списков, числа, структура плана до ингредиентов.

Проверка гоняет 5 атак, 374 сочетания порчи полей и 28 видов порчи внутри плана. После каждой приложение обязано открыться.

**Одно место остаётся открытым сознательно.** Пока работает `start.bat`, приложение и общая база видны всей локальной сети без пароля — иначе телефон до них не достучится. Дома это и есть задумка. В чужой сети закройте окно сервера и работайте через `overmoney.html` или через адрес.

## Чего оно не делает

- Не тянет цены с сайтов магазинов автоматически — цены обновляются вашими правками.
- Не учитывает акции и скидки по карте лояльности.
- Не умеет разделить обратно то, что слилось при объединении хозяйств: цены и кладовая останутся общими у обоих.
- Не синхронизируется, пока не подключён проект Supabase — до этого только выгрузка файлом.
