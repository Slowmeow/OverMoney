# OverMoney — продукты по бюджету

Планировщик недельного меню, который держит три вещи одновременно: **бюджет**, **калории с БЖУ** и **то, что уже лежит дома**.

Вы говорите: «15 000 ₽ в месяц на двоих». Приложение собирает неделю блюд под ваши нормы, разворачивает её в список покупок с реальными упаковками и ценами, вычитает содержимое кладовой и, если не влезает в деньги, **удешевляет рацион заменами, не трогая калории и белок**.

## Как запустить

**На компьютере:** двойной клик по `start.bat`. Браузер откроется сам — но не раньше, чем сервер будет готов отвечать. Приложение работает на `http://localhost:8777/`. Нужен установленный Python (он уже есть).

**На телефоне — одним файлом, без компьютера.** Это основной способ:

```
python build.py          собирает overmoney.html — 381 КБ, всё внутри
```

Отправьте `overmoney.html` на телефон любым способом (Telegram, почта, кабель, облако), откройте его там и выберите в меню браузера «Добавить на главный экран». Дальше приложение живёт с иконки: без интернета, без Wi-Fi и без включённого ноутбука. Список покупок открывается в магазине, где связи нет.

**На телефоне — через компьютер.** Пока `start.bat` работает, откройте на телефоне адрес вида `http://192.168.x.x:8777/` (он печатается в окне запуска, телефон должен быть в той же сети). В этом режиме компьютер и телефон работают с **общей базой** — файлом `data.json` рядом с приложением, — и правки с любого устройства видны везде.

Разница между способами одна и важная: одиночный файл хранит данные у себя в телефоне и с компьютером сам не синхронизируется. Перенос — через «Настройки → Данные → Выгрузить в файл» и загрузку копии на другом устройстве. Браузер может очистить своё хранилище сам, поэтому копию стоит выгружать раз в месяц.

## Что оно делает

- **Считает нормы** по формуле Mifflin-St Jeor для каждого едока отдельно (пол, возраст, рост, вес, активность, цель). Любую цифру можно перебить вручную.
- **Собирает неделю** из ~60 рецептов, подгоняя порции под калорийную долю каждого приёма пищи. Супы и рагу по умолчанию растягиваются на два дня.
- **Приоритезирует кладовую.** Внесли «картошка 4 кг, гречка 800 г» — приложение и меню перекроит в их сторону, и из списка покупок вычтет. В тестах это срезало неделю с 4629 ₽ до 3212 ₽.
- **Считает по упаковкам, а не по граммам.** Нужно 300 г риса — в списке будет пачка 800 г и её полная цена, а 500 г уйдут в кладовую на следующую неделю.
- **Удешевляет при нехватке бюджета** — заменами внутри роли: сыр → творог, фарш свино-говяжий → курица, гречка → перловка, батон → ржаной. Каждая замена откатывается, если калории уходят из допуска или белок падает ниже установленной границы.
- **Честно сдаётся,** когда бюджета не хватает физически: показывает самый дешёвый вариант, сохраняющий норму, и называет сумму, при которой задача решается.

## Про цены — важно

Стартовые цены в каталоге — это **оценка** уровня Пятёрочки и Магнита, а не живые данные. Они помечены знаком `~` и словом «не проверено».

Точность появляется после вашей первой закупки: в списке покупок у каждой позиции есть поле цены — поправьте там, где чек разошёлся с расчётом. Правка сохраняется с датой, и всё старше 30 дней снова помечается как непроверенное. Через две-три закупки каталог становится вашим личным и цифры сходятся с реальностью.

## Структура

```
index.html              экран приложения
css/app.css             оформление, светлая и тёмная темы
js/data/products.js     каталог: цены, БЖУ, упаковки, группы замен
js/data/recipes.js      рецепты (КБЖУ считается из продуктов, не прописан руками)
js/core/nutrition.js    нормы питания и КБЖУ блюд
js/core/store.js        состояние, хранение, бюджет
js/core/shopping.js     потребность → упаковки → цена, с вычетом кладовой
js/core/planner.js      сборка недели и подгонка под бюджет
js/ui/                  экраны: обзор, неделя, список, кладовая, цены, настройки
sw.js                   офлайн-кэш
serve.py                локальный сервер и общая база
build.py                сборка всего приложения в один файл для телефона
tests/run.js            проверка математики, без зависимостей
tests/render.js         проверка отрисовки экранов, нужен jsdom
start.bat               локальный запуск
```

## Как проверить, что цифры не врут

```
node tests/run.js
```

55 проверок за пару секунд, без установки чего-либо. Проверяется не «нажимается ли кнопка», а то, на что приложение опирается молча: что норма питания согласована сама с собой и совпадает с формулой Mifflin-St Jeor, что калорийность продуктов сходится с их БЖУ, что сумма стоимостей блюд равна чеку до копейки, что купленного хватает на все рецепты, что из кладовой не берётся больше, чем в ней лежит, что даты не уезжают на сутки и что подгонка под бюджет не достигает экономии недокормом.

Планировщик намеренно случаен, поэтому всё, что от него зависит, гоняется на **фиксированных посевах** генератора случайных чисел. Без этого два прогона несравнимы: непонятно, план подешевел от правки в коде или просто выпал другой набор блюд. В конце печатается быстродействие — на тех же посевах, поэтому цифры сравнимы между запусками.

Отдельно проверяется, что все семь экранов действительно строятся:

```
npm install jsdom     один раз
python build.py       собрать overmoney.html
node tests/render.js
```

Без jsdom этот тест честно пропускает себя, а не притворяется пройденным. Берёт он именно собранный `overmoney.html` — так заодно проверяется, что версия для телефона склеена в рабочем порядке.

## Чего оно не делает

- Не тянет цены с сайтов магазинов автоматически — цены обновляются вашими правками.
- Не синхронизируется между устройствами по сети — только выгрузкой файла.
- Не учитывает акции и скидки по карте лояльности.
